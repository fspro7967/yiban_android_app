# 复用清单：yiban_android_app → 本项目

> 勘察于 2026-11-04。结论先给：**语音层（合成 + 识别 + 模型解包 + 播放）是真实资产，值 3–5 天；界面层是空的，调度层一行都没有。**
> 技术栈实证：Qt **6.11.1** + `android_arm64_v8a` + `ANDROID_PLATFORM=android-28` + CMake 4.2.3 + ninja。
> **之前所有文档里写的"Qt 6.8 LTS"作废，统一按 6.11.1**——Pi 上的桌面 Qt 也必须装 6.11.1，否则同一份 QML 两边跑不起来。

| --- | --- | --- | --- |

| `include/sentencesplitter.h`、`src/sentencesplitter.cpp` | 28 + 84 | 长句切分，让 TTS 能一句一句流式出音 | A1 |

| 文件 | 行数 | 是什么 | 要改什么 |

## 3. 抽代码，不要抽类

`src/mainwindow.cpp`（**1091 行**）里混着 BLE 扫描、GATT、AI 大模型 API（OpenAI 兼容 + Ollama）、QSettings 配置、音频输出。只有两段与本事有关：

- **约 797–900 行**：`QAudioSink` 开设备、`8 kHz` 与设备采样率不一致时的重采样、`resume()` 语义、排空定时器。手机喇叭播报要走的就是这段。
- 其余（BLE / GATT / 大模型 / 配置页）**全是噪音**，一行都不要搬。

做法：新建 `AudioService`（QObject），只做 `play(pcm, sampleRate)` / `stop()` / `setVolume()`，内部 QAudioSink + 重采样。**不要继承 MainWindow，不要把它当 backend 单例。**

## 4. 没有的东西（这才是这周的活）

| 缺什么 | 影响 |
| --- | --- |
| `qml/Main.qml` = **0 字节** | 现在这个仓库**跑不起来**（`loadFromModule` 失败 → `rootObjects` 为空 → 返回 -1）。所以"跳过 Hello World"不成立：明天要写的就是一个最小 Main.qml |
| `core/`：调度、状态机、日志、幂等 | 一行都没有。这是本项目最值钱的部分（第 1、5 步） |
| SQLite 与三张表 | 无 |
| HTTP 客户端 + 重传队列 | 无（大模型那次调用不是我们的协议） |
| 家属端全部 | 无 |
| **AndroidManifest 权限** | 现状只有 `INTERNET`。缺 `RECORD_AUDIO`、`POST_NOTIFICATIONS`、`SCHEDULE_EXACT_ALARM`、`FOREGROUND_SERVICE`，也**没有 service 声明、没有 BOOT_COMPLETED**。我上一轮说"manifest 现成的"是错的，向你说清楚 |
| 锁屏唤起 / 前台服务 / 通知渠道 / 音频焦点 | 无。这是步骤 2 最难的部分，仍从零开始 |
| `third_party/` 里没有 Pi/Linux 的库 | `libsherpa-onnx-jni.so`、`libonnxruntime.so` 是 **Android arm64 的 JNI 包**，树莓派不能复用。Pi 端 TTS 用 `espeak-ng` 或 Linux aarch64 版 sherpa-onnx |

## 5. 净账

省下约 **3–5 天**（语音合成链路 + 模型解包 + 播放/重采样 + Android 构建配置）。**全部投给第 5 步**，不投给新功能。

真正的不确定性只剩一个：**Qt 6.11.1 + 这套 CMake 在你那台 root 的 Android 14 演示机上装得进、跑得起来、出声。** 这件事明天验，10 分钟就能有答案。
