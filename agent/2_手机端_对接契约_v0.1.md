# 手机端与后端对接契约

**收件人**：陈诺、何奕辰、王一丞 ｜ **版本**：v0.1 ｜ **发出**：2026-11-03

> 用途：你们写手机端时只对着这一份，不用去看报告里的架构章节。字段名以本文为准；要改，先在群里说，版本号加一。

---

## 一、访问方式

所有请求走 HTTPS，返回 JSON。除了配对那一个接口，其余都要带令牌：

```
Authorization: Bearer <token>
```

演示阶段如果后端还是固定令牌（`app-elder-001` 这种），先按固定值联调；换成配对码是后端的事，接口形状不变。

---

## 二、七个接口

| # | 方法与路径 | 请求关键字段 | 返回 | 说明 |
|---|---|---|---|---|
| 1 | `POST /auth/pair` | `pairing_code` | `elder_id, token` | 配对码换令牌。全系统唯一凭据 |
| 2 | `POST /plans` | `title, times[], rule{}, dose, active` | `plan` | 建计划。`rule` 见第三节 |
|   | `PATCH /plans/{id}` | 同上任意子集 | `plan` | 改或停用。不影响已发生的实例 |
| 3 | `GET /occurrences` | `elder_id, from, to` | `occurrence[]` | 查某段时间的实例及其状态 |
| 4 | `POST /occurrences/{id}/events` | `action, event_id, client_ts, note` | `event, duplicate?` | 确认/稍后/未确认。重复提交返回 `duplicate=true` |
| 5 | `POST /records` | `type, value, unit, at` | `record` | 新增记录 |
|   | `PATCH /records/{id}` | 同上 | `record` | 更正记录：写新事件，不覆盖旧值 |
| 6 | `GET /stats` | `elder_id, range=7d\|30d` | `daily[], weekly[]` | 日/周统计。统计口径由后端算，前端不要自己算 |
| 7 | `GET /alerts` | `elder_id` | `alert[]` | 未确认超时的告警列表 |

## 三、七种重复规则怎么写

`rule` 是一个对象，`kind` 决定其余字段。这是两边最容易写岔的地方，请照抄：

| kind | 其余字段 | 含义 |
|---|---|---|
| `daily` | — | 每天，按 `times[]` 里的时刻 |
| `interval` | `n, start` | 每 n 天一次 |
| `weekly` | `weekdays[1-7]` | 每周指定几天 |
| `monthly` | `day` | 每月某日 |
| `course` | `days, start` | 疗程：从 start 起连续 days 天 |
| `meal_offset` | `offset_minutes, anchor` | 相对餐时，例如餐前 30 分钟 |
| `once` | `at` | 一次性，指定时刻 |

## 四、状态枚举（不要自己造词）

`pending`（待提醒）→ `notified`（已提醒）→ `confirmed`（已确认）｜ `snoozed`（稍后）→ `missed`（未确认）→ `escalated`（已升级到家属）。

**只有后端能改状态。** 手机端只做一件事：把用户动作作为事件提交上去（接口 4），然后刷新显示。不要在客户端本地把状态改成"已确认"。

---

## 五、幂等键：三条必须遵守的规则

```
event_id = uuid5(occurrence_id + action + client_ts)
```

- **`client_ts` 在重试时必须保持不变。** 每次重试都取新时间，幂等就失效了——这是最常见的错。
- 断网时把事件排队，联网后按原样重发，不要重新生成 `id`。
- 后端返回 `duplicate=true` 时，当作成功处理，不要提示用户"失败了"。

---

## 六、时间怎么写

一律 ISO 8601 带时区，例如 `2026-11-05T08:00:00+08:00`。后端存 UTC，返回时带 `tz` 字段。

不要传 `YYYY-MM-DD HH:MM` 这种没有时区的字符串——换时区或夏令时会错位。

---

## 七、错误怎么处理

| 状态码 | 含义 | 手机端该做什么 |
|---|---|---|
| 401 | 令牌无效 | 回到配对页 |
| 403 | 跨家庭访问（访问了别人的数据） | 提示无权限，不要重试 |
| 404 | 实例不存在（可能已被改期） | 刷新列表 |
| 409 | 状态冲突（例如已确认又提交未确认） | 刷新后按最新状态显示 |
| 422 | 参数不合法（多半是 `rule` 写错） | 开发期直接看返回信息，别吞掉 |
