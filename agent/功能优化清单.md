# 功能优化与新功能清单

> 整理于 2026-11-16，基于提交 `e3e29e0` 的代码与 `agent/` 下的规划文档。
> 结论都来自读代码，没有上真机验证。编号 R*-* 指 [`需求扩展与技术路线.md`](需求扩展与技术路线.md) 里的需求编号。

总的判断：界面已经相当完整，现在最值得投入的不是新功能，而是让"提醒"和"呼救"这两件事真的成立。

## 一、先补的缺口（按优先级）

- [ ] **1. 呼救和"已通知家人"目前是假的。**
  `AppCore::sos()`（`src/vm/app_core.cpp:991`）只写一条日志并弹出"已通知家人"，没有任何东西发出去；
  提醒超时后的"已通知 XX"也一样。
  最小修法：倒计时结束后直接调起拨号，设置页已有现成的 `tel:` 写法（`qml/SettingsPage.qml:21`）。
  没配联系人时应明确提示"未设置家人电话"，而不是显示已通知。

- [ ] **2. 夜间安静会把呼救语音一起静音。**
  `qml/CallScreen.qml:28` 用的标签是 `"sos"`，而 `src/vm/device_vm.cpp:244` 只放行 `manual` 开头的标签。
  这和 R1-9"除 SOS 外不播报"相反，一行就能改。
  另：`buglist_ui.md` 第 10 条"夜间安静无效"还没关，原因未定位。

- [ ] **3. 提醒只有语音，没有铃声和震动。**
  关掉语音、夜间安静时段、或手机没装中文 TTS 引擎（国产机常见）时，到点提醒完全无声。
  建议加铃声和震动作为底线，夜间改为只震动。

- [ ] **4. 数据全在内存，重启即丢。**
  计划、记录、设置、联系人都不落盘。QtSql 已经链接进来了，
  可以先用 QSettings 存设置和联系人，再用 SQLite 存计划和实例。

- [ ] **5. App 不在前台就不会提醒。**
  调度靠 `onTick` 的 1 秒 QTimer，Manifest 只有 `INTERNET` 权限。
  需要 AlarmManager 精确闹钟、全屏通知和开机重排（R8-1 ～ R8-4）。
  这是最难的一块（要写 JNI），但它决定了"提醒不丢"能不能演示。

- [ ] **6. 升级逻辑放错了层，而且两处数值不一致。**
  2 分钟倒计时写死在 `qml/ReminderScreen.qml:16` 的界面计时器里，
  而计划里的 `escalateAfterMin` 是 15（`qml/AddReminderPage.qml:88`），界面没用它。
  建议把升级移进 AppCore 状态机，顺便做成 R1-3 的多级链路。

## 二、现有功能可以优化的地方

- [ ] **统计页只有提醒完成率。** 喝水、睡眠、活动记了却不展示，
  而记录页写着"今天的记录会用于本周统计"（`qml/RecordPage.qml:346`）。建议加三条趋势。
- [ ] **新建提醒要打字。** 加"吃药 / 测血压 / 复诊 / 喝水"模板一键生成，名称支持语音输入。
- [ ] **几个写死的值移到管理后台。** 喝水目标 8 杯、夜间时段 22–7 点、稍后固定 10 分钟。
- [ ] **暂停模式。** 已有 `skipToday`，可扩展成"外出或住院暂停到某日，恢复后不补发"（R1-7）。

## 三、值得考虑的新功能

前三条是 R 清单里没有的。

| 功能 | 为什么值得做 |
| --- | --- |
| 测量值记录 | 演示数据里有"测血压，记录数值"，但 App 没地方填。确认时弹大号数字键盘，统计页出趋势。 |
| 药品余量提醒 | 每次确认扣减库存，剩余不足 N 天时提醒家属买药。逻辑简单，很贴近真实需求。 |
| 提醒页显示药品照片 | 老人多靠外观认药而不是药名，由看护人在后台拍照。 |
| 每日平安签到 | 不用传感器的 R3-3：到上午某个时间仍无任何交互，就通知家属。 |
| 语音确认"我吃过了" | 仓库里已有 whisper 和离线 TTS 代码，但没接进构建，接上就是亮点（R4-5）。 |

## 四、工程卫生

- [ ] **89 MB 模型可能白占 APK 体积。** `android/assets/models` 在打包目录下，按 Qt 的规则会进 APK，
  但用它的代码（`speechsynthesizer.cpp`、`whisper_manager.cpp`、`mainwindow.cpp`）都没参与编译。
  要么接上（顺便解决第一节第 3 条的 TTS 依赖），要么移走。
- [ ] **README 里单测数量前后不一致**（一处写 24 例，一处写 16 例）。
- 仓库里的 `android_release.keystore` 及 `CMakeLists.txt` 中的密码仅用于测试签名，不需要处理。

## 建议顺序

一.1、一.2 → 一.3 → 一.4 → 一.5，之后再做"测量值记录"和"药品余量提醒"。
一.1 和一.2 改动很小，可以先做。
