## 2. 设计取舍（为什么这么写）

### 2.1 为什么平台层是 `Platform::` 一组自由函数，而不是一个 QObject

QML 不该看见它。B2 的东西只有 `DeviceVM` 一个出口，`Platform::` 只是 `DeviceVM` 的“手”。
做成 QObject 单例反而会诱使 QML 直接 `import` 平台层，那就破了“QML 只认 facade”的铁律。

代价是没法用信号，所以权限变化靠 `DeviceVM` 的 2 秒轮询兜（`tick()`）。权限弹窗是系统 UI，
用户点完回到应用，2 秒内 `permissions` 就会更新，够用，也省掉 `onRequestPermissionsResult` 的回调穿透。

### 2.2 为什么闹钟要“Java 侧再存一份”

`AlarmManager` 的闹钟**重启即失效**，而重建需要“几点、提醒什么”。开机那一刻 Qt 进程还没起、
`AppCore` 的计划表读不到，所以在 `SharedPreferences` 里存一份最小影子（`AlarmStore`）。

它**永远不是真相源**：应用一启动 `DeviceVM::rescheduleAlarms()` 就全清重排，覆盖它。
开机时错过的闹钟**不补响**（补响会吓人），交给状态机标 `missed`——这也是 bug #14 的正确行为。

### 2.3 为什么重排是“全清 + 全量重排”，不是增量

确认 / 推迟 / 删除 / 改时间 / 切演示域，五种操作都会改变“今天还剩哪些”。增量维护要处理
取消时机、推迟后的新时刻、跨天边界，错一个就会出现“已经确认了，晚上还被闹醒”。
今天最多十几条，全清重排的代价可以忽略，换来的是不可能不一致。

### 2.4 为什么夜间安静要放行 `sos`

原实现 `tag.startsWith("manual")` 才放行，于是 23:00 按呼救，`CallScreen` 里那句
“正在通知家人”是**静音**的。老人半夜出事，屏幕亮了但没声音，这是安全事故，不是体验问题。
现在 `sos` 和 `manual` 都放行，只有“到点自动播报”被静音——这才是“夜间安静”的本意。

### 2.5 为什么 `HttpClient` 重试要复用 `requestId`

规范 §9 写死了“传输层重试不重新生成 id”。如果每次重试换一个新的 `requestId`，`SyncVM`
会把一次上传看成三次，`pendingCount` 就永远归不了零。所以 `Job` 里存 `attempt`，
重试时只 `dispatch` 不动 `id`。

409 不重试、不当失败，原样 `reply(id, 409, body)` 交给上层——冲突要回滚本地乐观值，
那是 B1 的事，传输层不许自作主张。

## 3. 怎么验（★ 我没能在本机跑过，见 §4）

### 3.1 桌面（不需要手机）

```bash
cmake -S . -B build-verify -DCMAKE_BUILD_TYPE=Release \
      -DCMAKE_PREFIX_PATH=/opt/Qt/6.11.1/gcc_64 -DBUILD_TESTING=ON
cmake --build build-verify -j6

./build-verify/tests/tst_platform                              # 4 例，B2 的
./build-verify/yiban_android_app                               # 桌面照常跑，平台层是空实现
```

### 3.2 真机（M1 的验收动作）

```bash
cmake -S . -B build -DCMAKE_TOOLCHAIN_FILE=<Qt>/6.11.1/android_arm64_v8a/lib/cmake/Qt6/qt.toolchain.cmake \
      -DQT_HOST_PATH=<Qt>/6.11.1/gcc_64 -DBUILD_TESTING=OFF
cmake --build build --target apk -j6
adb install -r build/android-build/yiban_android_app.apk
```

装完依次确认（这就是 W2 周五要演的，不是额外要求）：

1. 首次启动 → 弹**通知**权限；点允许。
2. 进设置 → 夜间安静开关关掉再打开 → 应该看到 toast“22:00 起自动生效”（白天）。
3. 建一条 2 分钟后的提醒 → **锁屏扣桌上** → 到点自己亮屏 + 全屏提醒页 + 语音。
4. 打开“闹钟和提醒”权限（设置里若提示）；`adb shell dumpsys alarm | grep yiban` 能看到条目。
5. `adb reboot` → 开机后不打开应用，等到点 → 仍然响（`BootReceiver` 生效）。
6. 长按呼救 3 秒 → 倒计时 5 秒 → 真拨家属号；把 `CALL_PHONE` 拒掉再试 → 应该走短信。
7. `adb shell am kill com.yiban.elder` 后等一条提醒 → 仍能收到通知（走的是闹钟不是进程）。

### 3.3 抓日志

```bash
adb logcat -s Qt:A AndroidRuntime:E
adb shell dumpsys notification --noredact | grep -A5 yiban
```

## 4. 风险与未验证项（必须先看这段）

1. **本机没有 Qt / Android SDK，一行都没编译过。** 我是按 Qt 6.11 的 API 写的
   （`QNativeInterface::QAndroidApplication::context()`、`QJniObject::callStaticMethod`、
   `QNetworkRequest::setTransferTimeout`），但**第一次 `cmake --build` 很可能要修几个小错**。
   建议先只编桌面（§3.1），再编 APK——桌面能过就说明除 JNI 以外的都对了。
2. `QNetworkRequest::setTransferTimeout` 只在 Qt ≥ 6.7 时编译（已用 `QT_VERSION_CHECK` 包住），
   更早的 Qt 会自动跳过，重试机制仍然有效。
3. `BootReceiver` 用的是 `android:exported="false"`。系统广播对非导出组件可达，这是 Google 现行推荐；
   若某个国产 ROM 收不到 `BOOT_COMPLETED`，把它改成 `true` 试一次（先确认不是省电策略杀的）。
4. 没有声明 `USE_EXACT_ALARM`（那个权限在应用商店有政策限制，闹钟类才给）。现在走
   `SCHEDULE_EXACT_ALARM` + 用户授权，被拒时退化成 `setAndAllowWhileIdle`（最多晚几分钟）。
   演示机建议手动打开，否则“整点”会飘。
5. `android/assets/models/` 那 89 MB 离线 TTS 模型**现在没被用到**（语音走的是
   `QTextToSpeech` = 系统 TTS）。要不要删等 C1 定：删了 APK 小 89 MB，但没网的机器上就没中文语音了。
6. `mainwindow.cpp` 删了，里面的 `QAudioSink` 重采样段没抽成 `AudioService`——因为现在的音频路径
   是系统 TTS，不需要自己推 PCM。如果第 5 周要做离线语音，从 git 历史里捞回来（`git log -- src/mainwindow.cpp`）。
7. kiosk 用的是 `startLockTask()`，**没有设备管理员**时系统会弹“屏幕固定”确认框。
   真要做成不可退出的老人机，得配 device owner（`adb shell dpm set-device-owner`），那是 W5 的事。

## 6. 给另外两位的一句话

- **B1**：`AppCore` 需要给同步队列两个方法：`pendingEvents()` 和 `markSynced(eventIds)`。
  有了这两个，`SyncVM::retrySync()` 直接 `postJson("/events", ...)`，错误码我都按规范抛好了
  （`offline` / `network` / 409 走 `reply`）。
- **F1**：设置页“重新配对”接 `DeviceVM.pair()`；权限引导读 `DeviceVM.permissions`
  （里面是中文标签，未授权项就是不在列表里的那些）。`QML` 不用碰任何 Android API。
