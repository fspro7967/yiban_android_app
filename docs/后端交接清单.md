## 2. B1（何奕辰）：把 AppCore 换成真的

目标：**facade 不动，`qml/` 不动，只换 `app_core.cpp` 内部**。

### 2.1 必做

1. **SQLite 落库**（`plans` / `occurrences` / `events` / `records` 四张表，字段见规范 §3）。
   现在 `m_plans` 等 `QVariantList` 是内存，替换为查询即可，公开方法签名不变。
2. **状态机**：照规范 §5 的迁移表实现；`confirm/snooze/undo/escalate` 的错误码必须与
   `facade_errors.h` 一致（`already_confirmed`、`snooze_limit`、`nothing_to_undo`、`not_escalatable`）。
3. **occurrenceId 生成**：公式见规范 §2.2；**端上生成**，不要等后端下发。
4. **事件队列**：`appendEvent()` 现在直接进内存 list，改为"写 `events` 表 + `synced=0` + 唤醒 SyncVM"。
5. **统计**：`stats(days)` 从 occurrence 历史算，返回 §3.4 形状（`date/label/expected/confirmed/missed/rate/isToday`）。
6. **时间源**：`nowMs` 现在是 `QDateTime::currentMSecsSinceEpoch()`；接后端后改成
   "本地单调时钟 + 服务端偏移"，避免用户改系统时间导致漏提醒。

### 2.2 不做

- 不要给 QML 加方法、不要改 `occurrence`/`plan`/`record` 的键名。
- 不要在 AppCore 里发 HTTP——那是 B2 的 `HttpClient`，AppCore 只发信号/入队。

### 2.3 验收

```bash
cmake -S . -B build-prod -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=/opt/Qt/6.11.1/gcc_64
cmake --build build-prod -j8
QT_QPA_PLATFORM=offscreen ./build-prod/tests/tst_app_core   # 13 例必须全绿
```

替换实现后如果某条用例挂了，先看是不是形状/错误码变了，**不要改用例**——
用例就是契约（除 `init()` 里的 `resetDemo`，可换成清空测试库）。

## 3. B2（王一丞）：网络、系统、音频

### 3.1 必做

1. **`HttpClient` 真实实现**（`src/comm/`，唯一允许 `QNetworkAccessManager` 的地方）：
   - `postJson(path, body)` / `getJson(path, query)` 返回 `requestId`，异步回 `reply(requestId, status, body)` 或 `failed(requestId, code)`。
   - 基地址、配对 token 走 QSettings；`isOnline` 用 `QNetworkInformation` 或请求失败判定。
2. **7 个端点**（规范 §8）：`/v1/pair`、`/v1/events`、`/v1/plans`(GET/POST/PATCH/DELETE)、`/v1/state`、`/v1/alarm`、`/v1/records`。
   `POST /v1/events` 的 body 用 `SyncVM.eventLogCsv()` 背后的同一份事件（`eventId` 已按规范 §7 生成）。
3. **`SyncVM` 接真**：`syncState` 四态、`lastSyncTs`、`pendingCount`、指数退避、409 冲突回滚。
4. **TTS / 前台服务 / 精确闹钟**：
   - `DeviceVM::speak()` 已有 `QTextToSpeech`，Android 上换成系统 TTS + 夜间静默判断。
   - 锁屏全屏提醒需要前台服务 + `full-screen intent`；QML 的 `ReminderScreen` 只管应用内。
5. **配对流程**：`POST /v1/pair` → 写 `ProfileVM.applyProfile()` + `DeviceVM` 的 `paired/role`。

### 3.2 验收

- 拔网启动：`SyncVM.syncState == "offline"`，首页/提醒/记录/统计全部可用。
- 联网后 `pendingCount` 逐条归零，后端 DB 能看到 8 种 `action`。
- 改系统时间 ±1 小时，提醒不提前/不延后（时间源见 §2.1 第 6 条）。

## 5. 已知的洞（v1.1 未解决，别当成 bug）

1. **`PlanVM.createPlan` 是否对老人开放**：现在 UI 有"新建提醒"，需 A1 拍板；
   若关掉，给 `AddReminderPage` 加角色判断即可（facade 不变）。
2. **plans / records 写接口**：v1.0 冻结清单没有，v1.1 补了 4 个端点，需 A1 确认（规范 §8）。
3. **`/v1/alarm` 手动 SOS**：`occurrence_id` 可空 + `source:"manual"`，需 A1 确认（规范 §8.2）。
4. **`DeviceVM.pair()` 是同步 void**：真实配对是异步的，目前失败只发 `commandRejected`，
   界面没有"配对中"状态；如果要做，加一个 `pairing` 属性（改 facade 需三人同步）。
5. **演示钩子**：`triggerDemoReminder()`、`resetDemo()`、`YIBAN_DEV_SHOTS` 截图块只在开发构建用，
   发版前用 `-DYIBAN_DEV_SHOTS=OFF`（默认就是 OFF）即可。
